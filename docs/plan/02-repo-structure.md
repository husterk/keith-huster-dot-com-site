## The content model

The principle: **the layout is code, the words are data.** Adding a job, changing a number, rewriting a paragraph, or retiring the Tour Divide section someday means editing YAML, never touching a component. Each collection has a Zod schema in `src/content.config.ts` (see `samples/content.config.ts`), so the build refuses malformed content with a readable error pointing at the file and field.

### `site.yaml`

```yaml
- id: site
  name: Keith Huster
  headline: { lead: "Reliable", accent: "by design." }     # two parts so the accent word is styleable
  roles: "Senior / Staff Software Engineer · Engineering Manager"
  rolesShort: "Senior / Staff Engineer · Eng. Manager"
  location: "Remote from Orem, Utah"
  intro: >-
    I'm Keith Huster, Senior Software Engineer II and former Team Lead II ...
  cta: { primary: { label: "See the impact", href: "#impact" }, secondary: { label: "Download résumé", href: "/Keith-Huster-Resume.pdf" } }
  stats:
    - { value: ">99.9%", label: "availability on services handling billions of transactions a year" }
    - { value: "100+",   label: "engineers building on platform libraries I own" }
    - { value: "36",     label: "US patents, most as lead or sole inventor" }
    - { value: "2,745 mi", label: "Tour Divide finisher, 2025: self-supported, 27 days" }
  links: { email: husterk@gmail.com, linkedin: https://www.linkedin.com/in/husterk/, github: https://github.com/husterk }
```

### `impact.yaml`

```yaml

  title: Five core services moved to Kubernetes
  body: "Initiated and led the migration of five core services from EC2 to Amazon EKS, ..."
  result: { value: "5", label: "core services migrated" }
  tags: [AWS, EKS, HPA, KEDA, Terraform]
```

plus a `chips` list for the technology row. `leadership.yaml`, `patents.yaml` and `beyond.yaml` follow the same shape (heading, paragraphs, cells/boxes). Full drafts, populated with the final copy from `docs/design/COPY.md`, are in `samples/content/`.

### Markdown for prose pages

`colophon.md` is ordinary Markdown with frontmatter (`title`, `updated`). It renders through the Base layout with the site's type styles, so it needs no components. Any future write-up (a case study on the on-call design, a "now" page) is a Markdown file in `src/content/pages/` rendered by a `[slug].astro` route; that route is one file and can be added when the first such page exists.

### Editing workflow (the whole thing)

1. Open the YAML file on GitHub (or locally), change the text, commit to a branch.
2. The PR check builds the site; if the YAML is wrong the check fails and says why. The PR gets a preview URL.
3. Merge. The deploy workflow publishes within about two minutes.

For a quick fix from a phone, GitHub's web editor on `main` works; the deploy workflow still validates before publishing, and a failed build leaves the old version live.

## Templates and styling notes

- Start from `docs/design/preview/index.html`: its `<style>` block becomes `tokens.css` + `base.css` + `sections.css` (swap container queries for media queries at 1099px and 699px), and each section's markup becomes a component that takes its data from a collection.
- Scenes: each SVG becomes an `.astro` component. `Strip.astro` wraps a scene with the `--h` / `--cx` / `--k` mechanism from the spec (or the `viewBox` + `preserveAspectRatio="xMidYMax slice"` equivalent). The accent color is `var(--accent)` inside the SVGs so one token recolors everything.
- The rider: one `Rider.astro` with `pose` (`riding` | `camp` | `finish`) props, placed by each scene.
- The elevation chart is generated from `experience.yaml` in `ElevationChart.astro` (a few lines of arithmetic, no charting library). On phone it's hidden and the cards carry the content, exactly as in the mockup.
- Mobile menu: a `<button aria-expanded>` toggling a `<dialog>` or an overlay `<nav>`; ~20 lines of vanilla JS in a `<script>` tag. Focus is trapped while open; Escape closes.
- Motion: CSS-only bob on the rider; optional parallax in a 30-line `<script>` gated on `prefers-reduced-motion: no-preference` and `IntersectionObserver`. Ship the site without parallax first; add it in milestone 5 if it still feels worth it.
- Local development: `mise install` (Bun and Node from `mise.toml`), `bun install`, then `bun run dev` (`astro dev`, already inside workerd with the rate-limit and vars bindings from `wrangler.jsonc`); `bun run build && bun run preview` (`astro preview`) runs the production Worker locally. Node 24 comes from mise as well (Bun runs these CLIs on Node; see 01). Tasks stay in `package.json` scripts run by `bun run`; mise pins tools only.
- Metadata: `<title>`, description, canonical, Open Graph and Twitter tags, JSON-LD `Person` (name, jobTitle, sameAs LinkedIn/GitHub), favicon SVG, `theme-color`.
